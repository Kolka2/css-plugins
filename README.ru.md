# css-plugins

[English version](README.md)

SourceMod-плагины для Counter-Strike: Source.

Код написан с помощью ИИ ([Claude Code](https://claude.com/claude-code)) под руководством автора. На живом сервере проверено пока не всё: у каждого плагина есть `TEST_CHECKLIST.md`, где перечислено, что проверено, а что нет.

## Требования

- выделенный сервер Counter-Strike: Source (обновление февраля 2025, 64-бит)
- Metamod:Source 1.12
- SourceMod 1.12

Поддерживается только CS:S.

## Плагины

| Плагин | Что делает | Состояние | Документация |
|---|---|---|---|
| `nadethrow` | Броски гранат, как в CS:GO: ЛКМ, ЛКМ + ПКМ и ПКМ дают броски разной силы. Есть API для других плагинов. | Готов. Основная механика проверена на сервере, остальной чек-лист ждёт проверки. | [README](docs/nadethrow/README.md), [чек-лист](docs/nadethrow/TEST_CHECKLIST.md) |
| `teammoney` | Во время фризтайма показывает каждому игроку деньги, гранаты и наборы сапёра его команды. | Готов, ждёт проверки на сервере. | [README](docs/teammoney/README.md), [чек-лист](docs/teammoney/TEST_CHECKLIST.md) |

В планах: режим тренировки гранат (`nadepractice`), сохранённые раскидки и выходы (`lineups`, `executes`), управление ботами и более осмысленные боты (`botcontrol`, `botassist`, `botnav`).

Тексты для игроков переведены на английский и русский и показываются каждому на его языке.

## Установка

Готовых бинарников пока нет, поэтому сначала соберите плагины (см. ниже). Затем скопируйте в папку `cstrike/` сервера:

- `build/<плагин>.smx` → `addons/sourcemod/plugins/`
- `translations/` → `addons/sourcemod/translations/`

Квары и особенности каждого плагина описаны в его README.

## Сборка

Компилятора SourcePawn и include-файлов SourceMod в репозитории нет. Их нужно взять из пакета SourceMod 1.12:

1. Скачайте SourceMod 1.12 для своей ОС с <https://www.sourcemod.net/downloads.php>.
2. Из папки `addons/sourcemod/scripting/` пакета скопируйте в папку `tools/` этого репозитория:
   - компилятор: `spcomp` на Linux, `spcomp64.exe` или `spcomp.exe` на Windows;
   - папку `include/` целиком, как `tools/include/`.

Должно получиться так:

```
tools/
  spcomp            (или spcomp64.exe / spcomp.exe)
  include/
    sourcemod.inc
    ...
```

После этого запустите из корня репозитория (на Windows — в Git Bash или MSYS2):

```
./build.sh              # собрать все плагины в build/
./build.sh nadethrow    # собрать один плагин
```

Чтобы взять компилятор из другого места, задайте `SPCOMP=/путь/к/spcomp`. Include-файлы при этом всё равно читаются из `tools/include/`.

## Структура репозитория

| Путь | Что там |
|---|---|
| `scripting/` | исходники плагинов; в `scripting/include/` — их публичные API |
| `translations/` | переводы (английский и русский) |
| `docs/<плагин>/` | README, чек-лист проверки и журнал работы по каждому плагину |
| `templates/` | шаблоны: плагин-сервис, его API и плагин с необязательной зависимостью |
| `ARCHITECTURE.md` | архитектура и правила написания всех плагинов |
| `CLAUDE.md` | правила для ИИ-агента |
| `tasks/` | задания для ИИ-агента и их очередь |
| `build.sh` | скрипт сборки |

## Разработка

Плагины пишутся в сессиях с ИИ-агентом, и файлы, по которым он работает, лежат в репозитории:

- `CLAUDE.md` — рабочие правила агента: сборка, стиль кода, коммиты.
- `ARCHITECTURE.md` — слои плагинов, зависимости, правила именования и API.
- `tasks/` — по заданию на плагин; `tasks/README.md` — очередь заданий.
- `docs/<плагин>/PROGRESS.md` — текущее состояние работы и принятые решения.
- `docs/<плагин>/TEST_CHECKLIST.md` — что нужно проверить на настоящем сервере. В среде разработки сервера CS:S нет, поэтому всё, что зависит от поведения движка, помечено в коде `CSS-VERIFY` и перечислено здесь.

Эти рабочие документы написаны на русском. Комментарии в коде, описания кваров и сообщения в логах — на английском.
